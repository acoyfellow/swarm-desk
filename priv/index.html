Swarm desk · live on Cloudflare

1,000 support tickets. One agent each. Code acts only when the model is sure.

Each ticket gets its own agent: a tiny Elixir process. Every agent asks one model, Clef, two questions and gets odds back. A three-line rule in plain code decides: act, send to a person, or block. Press Go and watch.

1 · FAN OUTOne Jido agent per ticket, 200 thinking at a time.
2 · ASKClef: "What should support do?" and "Is this an attack?" With odds.
3 · DECIDE IN CODEAttack ≥ 50% → block. Action ≥ 85% → act. Else → a person.
4 · RECEIPTEvery choice keeps its odds. Click any square to see why.

Try to fool it

Why many small agentsThe BEAM runs a million cheap processes. One slow or broken ticket never blocks the rest. Speed is set by the model, not by the code.
Why odds, not wordsClef returns a number per option. Code can test a number. A threshold is a policy you can read, change and audit.
Why "a person" is a resultThe system does not guess. When it is not sure, it says so, and a human gets a short queue instead of the whole pile.
Model: Clef (@cf/cloudflare/clef) on Workers AI, through a Worker AI binding · Agents: Elixir + Jido in a Cloudflare Container (standard-2) · Tickets are synthetic: 95% normal, 5% attacks · Cost is input tokens × catalog price · Code: swarm-desk

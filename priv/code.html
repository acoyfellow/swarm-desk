Swarm code · one coding agent per task

16 coding tasks. 16 agents at once. Code ships only what passes and Clef trusts.

Each agent is a real coding agent: its own copy of the repository, a model in a tool loop, and a test runner. All 16 start at the same moment. When an agent finishes, its own test suite and Clef decide: ship, or send it to a person. Tests the agent never saw then grade the result.

1 · FAN OUT16 BEAM processes, one per task, each with its own workspace.
2 · WORKSonnet reads, edits and runs the tests, up to 30 tool turns.
3 · DECIDE IN CODESuite green and Clef ship odds ≥ 85% → ship. Else → a person.
4 · GRADEHidden tests the agent never saw say if the ship was right.

Why one process per agentAn agent spends almost all its time waiting on the model. On the BEAM a waiting process costs a few KB, so 16 or 1,600 cost the same to the machine. A crash stays inside its own task.
Why tests and oddsThe agent's own suite is a hard fact. Clef's ship odds catch what tests miss: unrelated edits, missing parts. Code needs both before it ships.
What this does not showOne small repository. One model. Running 8 agents on the same task did not beat 1 here: every attempt passed. Breadth, not voting, is the win.
Tasks and hidden tests: the "tally" benchmark from fire_trident (MIT), a 20-file TypeScript shop · Agents: Elixir processes, model claude-sonnet-5 via the OpenCode gateway · Judge: Clef (@cf/cloudflare/clef) on Workers AI · Cost at list price: $3 / $15 per M tokens
